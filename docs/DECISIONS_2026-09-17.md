# 확정 요구사항과 구현 기준

우선순위는 2026-09-17 사용자 결정, 인수인계 v1.1, 이전 v1.0 순서다. 인식 기술은 사용자가 검증한 디렉터리의 PARSeq/OpenCV/zxing를 유지한다. 인수인계 문서의 인식 모델 교체 제안은 적용하지 않는다. 문서의 하드웨어 정보는 기준으로 사용하되 실물 단자·명판·극성을 시험 없이 확정하지 않는다.

| 사용자 결정 | 적용 |
|---|---|
| 반드시 멈춰서 검사 | 모터 OFF, DI3 정지 피드백, 실측 안정화 시간, 새 프레임, 단일 제품 검출 순으로 검사 |
| 제품 하나=한 건 | session/product 중복 계수 제약, 동일 제품 재검사 시도 번호, 배출 센서 확인 |
| 바코드 선택 항목 | 시작 시 선택한 경우에만 필수 판정에 포함 |
| 목표 하나라도 미판독/불일치면 즉시 중지 | HOLD 래치, 작업자 조치, 자동 복구 없음. 검사 중 모터는 이미 OFF |
| 기준 데이터 직접 제공 | 헤지스 제공 127행 검증, 기타 메이커 EPC/바코드 JSON 입력·내보내기 |
| 수량 수동 보정 | 변경량·이유·사용자 감사 기록, 자동 추정 보정 없음 |
| 한 컴퓨터/오프라인 | 127.0.0.1 단일 서버·SQLite·로컬 모델·로컬 글꼴·패키지 묶음 |
| 옵션 직접 추가/삭제/선택 | 메이커별 동적 옵션 편집, 운전 시 목표값 선택, 작업 중 설정 잠금 |
| 확인 가능한 장비 정보 모두 표시 | CPU/RAM/디스크/프로세스/온도/전원 센서, I/O 원시값·KM2·허가·카메라·모델·RFID, 미계측은 미확인 |
| 파이프라인 그림 보류 | 활성 화면에 그림 없음 |
| 브라우저 직접 확인 금지 | 빌드·jsdom·API/실제 모델 테스트만 수행; 브라우저·스크린샷 미실시 |

## 미정 사항을 대신 결정하지 않은 부분

- 제품 검출 라이브러리 이름/경로/모델: 제공받은 뒤 기존 라이브러리를 어댑터에 연결한다. 대체 모델을 임의로 선택하지 않았다.
- 제품 간격, 목표 분당 처리량, 벨트 속도, 안정화·피드백·배출 제한시간, 센서 해제 시간: 실측 후 확정한다.
- OCR 촬영 영역·문자 품질 임계값·정지 촬영 조명/초점: 실물 표본으로 확정한다.
- 메이커별 공식 데이터와 바코드 표: 제공받은 범위만 사용한다. 헤지스 CRC는 무결성 검사이지 정품 인증이 아니다.
- 물리 START 관측 접점, 추가 입력 결선, 출력 OFF 극성, OS/프로세스 정지 시 차단: 실물 설계·시험 대상이다.
- 이미지 보존 기간/외부 저장 매체/삭제 정책: 자동 삭제를 켜지 않았다. 부족한 저장 공간에서는 운전을 차단한다.

## v1.1 적용과 해석

문서의 모터 1대, US-52 공장 하네스, J2 DI/DO, USB-TTL RFID, K0 SAFE24/RUN24, 24V 전원과 12/5V 변환 구성을 따른다. 하드웨어 핀 정의는 아래 인수 시험 문서에 고정했다. 원격 관제/VLAN 서버는 한 컴퓨터라는 사용자 결정에 따라 loopback으로 제한했다.

문서의 이동 영상 FPS/속도 지표는 정지 검사 공정에 맞춰 현장 승인 기준을 다시 정해야 한다. 소프트웨어는 p50/p95/p99 실제 검사시간을 기록한다. 기존 1,000건·8시간 이상 인수 시험은 여전히 남아 있다. 가능한 경우 동일 빌드로 72시간 시험한다.

운영 권한·변경 이력·일일 DB 백업·릴리스 해시·재시작 자동 운전 금지·명령 TTL/멱등성·연결 끊김 표시를 구현했다. 독립 프로세스 예시는 이 구현에서 단일 로컬 서비스의 전용 I/O 소유자와 추론 작업으로 구성했다. 소프트웨어 lease는 OS/프로세스 중단 시 물리 차단을 보장하지 않는다. 이 차이는 실제 정지 회로 시험이 끝날 때까지 실물 운전을 차단하는 이유다.
