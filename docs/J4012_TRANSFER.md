# J4012로 옮겨 첫 장비 시험하기

작성일: 2026년 9월 18일

대상은 사용자가 확인한 reComputer Industrial J4012다. 이 장비의 모듈은 Jetson Orin NX 16GB다. 구형 Jetson Nano 설치 방법과 구분한다.

## 지금 준비한 파일

`txrx-j4012-transfer-20260918.zip`은 현재 작업 폴더의 실행 코드, 빌드된 화면, 기존 PARSeq 모델과 설정 파일을 담는다. 최신 장비 시험 코드도 포함한다. Git에 아직 커밋하지 않은 변경이 있으므로 현재 GitHub 저장소를 복제하는 것과 내용이 다르다.

이 파일은 이관용 묶음이다. Jetson용 Python 설치 패키지, NVIDIA PyTorch, Ubuntu 설치 패키지는 포함하지 않는다. Windows용 오프라인 ZIP이나 Windows 가상환경으로 대체하면 안 된다. 실제 JetPack과 Python 버전 확인 후 ARM64 설치물을 준비한다. 실행 중 외부 서버를 사용하지 않는다.

Windows의 운영 DB, 비밀번호, 기존 시험 사진과 작업 기록은 포함하지 않는다. 새 장비에서 환경 설정에 처음 들어가면 사용할 비밀번호를 지정한다. 기존 PC와 같게 쓰려면 이때 `123456`을 지정한다. 브랜드의 기본 규칙 파일은 포함하지만 Windows 화면에서 DB에 저장한 변경 사항은 자동 이관되지 않는다.

## 1. 먼저 부팅

모니터, 키보드와 마우스를 연결하고 장비를 부팅한다. 처음 실행되는 Ubuntu 설정에서 사용자와 비밀번호를 만든다. 여기서 만드는 것은 Linux 사용자이며 앱 계정 생성과는 별개다.

기존 운영체제가 있으면 우선 그대로 사용한다. 앱을 시험하기 위해 바로 재설치하거나 JetPack을 업그레이드하지 않는다. 인수인계의 기준은 JetPack 6.1, L4T 36.4.0, Ubuntu 22.04, Python 3.10이지만 실제 설치 버전을 확인해야 한다.

터미널에서 다음을 실행한다. 모두 읽기 전용이며 출력을 켜지 않는다.

```bash
cat /proc/device-tree/model
cat /etc/nv_tegra_release
python3 --version
uname -m
```

결과를 확인한 뒤 설치 패키지를 선택한다. `aarch64`가 ARM64다. Python 3.8 환경이면 현재 코드를 그대로 실행할 수 없으므로 시스템 Python을 임의로 교체하지 말고 설치 경로를 먼저 확정한다.

## 2. 파일 복사

USB 저장장치로 이관 ZIP과 같은 이름의 `.sha256` 파일을 J4012의 다운로드 폴더에 복사한다. 파일 관리자에서 ZIP을 새 폴더에 풀어도 된다. 기존 앱 폴더 위에 덮어쓰지 않는다.

터미널을 쓸 경우 두 파일이 `~/Downloads`에 있다고 가정한다. 실제 다운로드 폴더 이름이 다르면 경로를 바꾼다.

```bash
cd ~/Downloads
sha256sum -c txrx-j4012-transfer-20260918.zip.sha256
unzip txrx-j4012-transfer-20260918.zip -d ~/TxRx-1-20260918
cd ~/TxRx-1-20260918
python3 scripts/verify_release.py
```

SHA256 검사에서 `OK`, 파일 검사에서 `verified_files`가 나오면 전송된 파일의 무결성을 확인한 것이다. 이는 실물 장치 시험 통과를 뜻하지 않는다.

## 3. 버전 확인 후 설치할 항목

| 용도 | 필요한 항목 |
|---|---|
| 웹 화면과 서버 | Python 가상환경, requirements-station.txt의 패키지 |
| USB 영상과 원본 저장 | ARM64용 NumPy와 OpenCV, V4L2 지원 |
| 해상도, 노출과 초점 설정 | Ubuntu의 v4l-utils 패키지에 있는 v4l2-ctl |
| GPIO 입력과 출력 | gpiod Python 2.x API와 장치 접근 권한 |
| RFID | pyserial과 실제 직렬 포트 접근 권한 |
| OCR 추론 | 해당 JetPack에 맞는 NVIDIA PyTorch와 TorchVision, 기존 OCR 의존성 |

카메라, 센서, LED, 모터와 RFID 개별 시험에는 PyTorch 모델 로딩이 필요 없다. OCR 시험은 AI 의존성을 설치한 다음 진행한다. `requirements.txt`의 일반 CUDA 설치 예시를 Jetson에 그대로 적용하지 않는다.

인터넷 없는 설치를 위해서는 대상 버전에 맞는 Python wheel과 Ubuntu 패키지 및 의존성을 미리 받아 옮겨야 한다. 이 이관 ZIP만으로 오프라인 설치가 끝났다고 간주하지 않는다. 현재는 버전별 설치물 확정 전이므로 설치 명령을 임의로 고정하지 않았다.

## 4. 개별 장비 시험 서버 실행

설치가 완료된 가상환경 이름을 `.venv-bench`로 사용할 예정이다. 그 환경이 준비된 뒤 아래 명령으로 실행한다.

```bash
cd ~/TxRx-1-20260918
.venv-bench/bin/python -m uvicorn station.app:create_app --factory --host 127.0.0.1 --port 8000 --workers 1
```

서버 터미널은 열어 둔다. J4012 자체 브라우저에서 `http://127.0.0.1:8000/`에 접속한다. Windows PC의 같은 주소는 Windows 서버를 뜻하며 J4012에 접속하는 주소가 아니다.

이 명령은 AI 의존성까지 요구하는 전체 운전 사전 점검과 구분한 개별 장비 시험용 실행이다. `config/station.json`의 `mode`는 `REPLAY`로 유지한다. 장비 점검의 개별 시험 기능은 이 상태에서도 실제 카메라, GPIO와 RFID에 연결한다. `REPLAY`라는 이름만 보고 모든 장치가 모의 동작한다고 생각하면 안 된다. 입력 연결, 시험 가동과 태그 읽기는 실제 장치를 조작한다.

생산 운전 승인 항목은 그대로 유지된다. 메인 화면에서 생산 작업을 시작하지 말고 환경 설정의 장비 연결 탭과 장비 점검 화면에서 시험한다. 정지할 때는 화면의 시험 전체 정지를 먼저 누르고 출력을 확인한 뒤 서버 터미널에서 Ctrl+C를 누른다.

## 5. 장치 시험 순서

### 카메라

1. B0478을 J4012의 USB 3 호스트 포트에 연결한다. 본체 USB-C Device/Debug 포트와 구분한다.
2. 환경 설정에 들어가 장비 연결 탭을 연다.
3. 장치 찾기에서 실제 카메라를 고르고 설정 읽기를 누른다.
4. 장치가 제공한 목록에서 우선 1920×1080 모드를 고르고 시험 적용한다.
5. 실제 촬영 거리에서 초점과 노출을 조절한다. 자동 제어가 켜져 있으면 해당 수동값이 잠길 수 있다.
6. 영상이 들어오면 적용하고 저장한다. 장비 점검에서 원본 사진을 촬영한다.
7. 앱을 다시 실행한 뒤 저장된 카메라 연결과 설정 복원을 확인한다. REPLAY에서 카메라는 자동으로 열지 않으므로 연결 버튼을 사용한다.

다른 카메라 프로그램은 먼저 닫는다. 해상도와 제어 범위는 실제 장치가 반환한 값을 따른다. B0478의 전동 초점과 자동 초점은 같은 뜻이 아니다. 자동 초점 항목이 없으면 수동 초점으로 맞춘다.

### 센서

1. 장비 점검에서 입력 연결을 누른다. 이 기능은 출력 설정 없이 입력만 요청한다.
2. 센서마다 물체를 넣고 빼며 원시값과 변화 횟수가 바뀌는지 확인한다.
3. 실측한 감지값을 환경 설정에 저장한다. 아직 모르는 극성을 추측해 입력하지 않는다.

장치 권한 오류나 GPIO 번호 오류가 나면 메시지를 기록한다. 전체 서버를 sudo로 실행하거나 임의 핀에 출력 명령을 보내 해결하지 않는다. 실제 BSP의 GPIO 장치와 접근 권한을 먼저 확인한다.

### LED와 모터

출력 ON 값, 운전 허가 입력, 접촉기 응답 시간과 배선 및 물리 정지 회로를 확인한 뒤 환경 설정에 저장한다. 확인 항목은 실제 확인 후 표시한다. 현재 설정값만으로 연결된 배선이 검증된 것은 아니다.

1. 모터 동력을 분리한 상태에서 출력과 릴레이 동작을 먼저 확인한다.
2. LED를 5초 켜고 자동으로 꺼지는지, 모터 출력에 영향이 없는지 확인한다.
3. 모터 시험 조건을 갖춘 다음 0.5초 가동으로 시작한다. 동작 방향, 접촉기 피드백과 실제 정지를 확인한다.
4. 시험 전체 정지와 물리 정지 회로를 각각 확인한다.

설정이 없거나 허가 입력 및 접촉기 피드백이 맞지 않으면 시험이 차단된다. 이를 통과하려고 임의값을 넣지 않는다. 앱은 모터 속도를 설정하지 않으며 기존 US-52에서 조절한다. LED는 켜기와 끄기 기능이다.

### RFID

실제 리더의 포트와 지원 명령 규격을 확인한다. 환경 설정에서 RFID 포트와 읽기 시간을 저장한 뒤 태그 읽기를 실행한다. 표시된 EPC를 실제 기준 데이터와 비교한다. 포트가 열리는 것만으로 리더 명령 규격까지 호환된 것은 아니다.

## 6. 첫 시험에서 기록할 결과

| 항목 | 남길 결과 |
|---|---|
| 실행 환경 | 본체 모델, L4T와 Python 버전 |
| 카메라 | 장치 경로, 선택한 해상도와 FPS, 원본 사진, 설정 복원 결과 |
| 센서 | 센서별 감지와 해제 원시값, 반복 변화 여부 |
| LED | 실제 점등과 소등, 제한 시간 종료 |
| 모터 | 출력 극성, 운전 허가와 KM2 피드백, 정지 결과 |
| RFID | 포트, 실제 EPC와 반복 읽기 결과 |

장치별 결과가 나온 다음 필요한 항목만 수정하고 재시험한다. 현재 Windows 소프트웨어 검증은 J4012 실물 호환 검증을 대신하지 않는다. 이동 중 촬영 공정은 보류된 후속 작업이며 이번 개별 장비 시험으로 완료되는 것이 아니다.
