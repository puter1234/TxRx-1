# 생산 RFID 읽기 설정

설정 위치: 환경 설정 > 브랜드 관리 > 해당 브랜드 상세 설정 > 촬영과 센서

해당 브랜드에 RFID 검사를 사용하도록 지정하면 다음 세 항목이 표시된다.

| 항목 | 의미 | 기본값 |
|---|---|---|
| RFID 첫 읽기 (ms) | DI1 입력 0 이후 첫 시도를 시작하는 시간 | 100ms |
| RFID 최대 횟수 | 한 제품에 읽기 명령을 보낼 최대 횟수 | 3회 |
| RFID 읽기 간격 (ms) | 이전 시도 시작부터 다음 시도 시작까지의 최소 간격 | 100ms |

최대 횟수는 1~100회, 간격은 20~10000ms다. 설정은 브랜드의 작업 프리셋에 저장되며 작업을 만들 때 해당 버전의 값으로 고정된다. 새 항목이 없는 기존 프리셋에는 기본값을 적용한다.

예를 들어 첫 읽기 100ms, 최대 3회, 간격 100ms이면 DI1 이후 100ms, 200ms, 300ms에 시도한다. 두 번째에서 읽히면 세 번째 명령을 보내지 않는다. 한 시도의 응답 대기 한도도 읽기 간격과 같다. 장치 응답 처리나 운영체제 일정 때문에 늦어지면 추가 명령을 한꺼번에 보내지 않고 실제 시도 시작부터 간격을 다시 계산한다.

## 판정

- 태그 하나를 읽으면 그 결과로 브랜드 규칙과 작업 조건을 확인한다.
- 다른 상품을 읽거나 한 수신 묶음에서 서로 다른 태그를 읽으면 즉시 실패로 정지한다.
- 무응답이나 리더의 미인식 응답은 다음 시도로 넘어간다. 최대 횟수까지 모두 미인식이면 정지한다.
- 연결 오류, 잘못된 프레임, 장치 오류는 미인식으로 숨기지 않고 중단한다.
- 카메라 복구 중에도 이미 보낸 명령 횟수를 유지한다. 완료된 판독 결과를 다시 읽지 않는다.
- 수동 정지는 남은 시도를 취소한다. 정지 이후 도착한 결과는 계수에 반영하지 않는다.

검사 완료 제한은 `첫 읽기 지연 + 최대 횟수 × 읽기 간격`보다 길어야 한다. RFID를 사용하지 않는 작업에는 이 조건을 적용하지 않는다.

## 구현과 확인 범위

DI1 생산 경로는 `FlowCycle.read_rfid`에서 시도를 관리한다. 리더에는 기존 `0x27` 명령의 반복 횟수를 1로 지정해 보내고, 첫 태그 수신이나 응답 대기 종료 후 `0x28`로 중지한다. 미인식 응답 `0x15`와 다른 장치 오류를 구분한다. 장비의 독립 RFID 시험은 [RFID_BENCH.md](RFID_BENCH.md)의 5회 반복 요청과 대기 조건을 사용하며 생산 시도 횟수에는 영향을 주지 않는다.

검사 기록에는 실제 시도 횟수 `rfid_attempts`와 각 시도의 시작 지연, 상태, 수신 태그 `rfid_reads`를 남긴다. 같은 EPC의 중복 수신을 제품 수량에 더하지 않는다.

직렬 명령 바이트, 단발 응답, 미인식과 오류 구분, 첫 인식에서 종료, 시도 간격, 카메라 복구 후 최대 횟수 유지, 수동 정지, 브랜드 설정 저장과 작업 전달을 모의 장치로 검증했다. 서버와 영상 처리 검사 304개, 화면 검사 52개가 통과했고 TypeScript 검사와 배포 빌드도 통과했다. Chromium에서 기존 프리셋의 기본값 표시, 수정 저장, 새로고침 후 값 유지와 화면 너비를 확인했다. 실물 리더의 응답과 현장 인식률은 클라우드에서 측정하지 않았다.
