# J4012 초기 시험과 Arducam B0478 적용 검토

후속 구현 안내: 이 문서는 조사 당시의 상태를 기록한다. 이후 장비 개별 시험과 USB 카메라 설정 기능을 구현했다. 현재 사용법과 검증 범위는 [DEVICE_TESTS.md](DEVICE_TESTS.md)를 따른다. 실물 검증 상태는 여전히 NOT_VERIFIED다.

확인일: 2026년 9월 18일
검토한 코드: a454336d39c3b0627ca9f5282173577ffc65042f
실물 검증 상태: NOT_VERIFIED

사용자가 본체를 reComputer Industrial J4012로 확인했다. 카메라는 새로 받은 Arducam B0478이다. 이 문서는 조사 결과와 개발 계획이며, 카메라 지원 구현 또는 현장 시험 완료 보고가 아니다.

추가 사용자 요구: 모터, LED, 센서, 카메라 모두 독립해서 시험할 수 있어야 한다. 촬영 요구는 이동 중 촬영으로 갱신되었으며 구현 변경은 사용자의 지시에 따라 보류한다. 아래 정지 검사 내용은 현재 구현의 검증 기준이며 최종 공정 방식으로 다시 확정한 것이 아니다.

## 현재 가능한 시험

현재 127.0.0.1:8000 서버를 읽기 전용 API로 확인했다. /api/health/live는 mode=REPLAY, /api/health/ready는 hardware_ready=false를 반환했다. 설정값과 현장 승인 항목이 비어 있고 실물 I/O도 연결되지 않은 상태다. 이 결과는 J4012에서 수집한 결과가 아니다.

| 항목 | 현재 구현 | 초기 시험에 부족한 부분 |
|---|---|---|
| 센서 | 장비 점검의 신호 확인은 현재 DI 원시값을 읽는다 | 입력만 독립해서 여는 시험 경로가 없다. 현재 GpioIO는 출력 극성, 허가 입력, 접촉기 응답 시간까지 있어야 생성된다. 감지 반복과 변화 시각 시험도 필요하다 |
| 출력과 컨베이어 | 운전 제어, STOP, 허가와 접촉기 피드백 감시 코드가 있다 | 독립 DO 시험이나 짧은 수동 시험 기능은 없다. 장비 화면의 벨트 가동은 생산 운전 시작 명령이다 |
| LED | DO2 조명 켜기와 끄기 코드가 있다 | 별도 LED 시험 API와 버튼이 없다. led_requested는 명령이며 led_confirmed는 미확인이다. 실제 점등 피드백은 없다 |
| RFID | 실제 태그 수집 시험 경로가 있다 | 실제 리더 명령 응답과 포트, 읽기 시간, 정지 피드백을 확인해야 한다 |
| OCR | 장비 점검의 모델 확인은 모델을 불러온다 | 카메라로 촬영한 문자를 판독하는 시험은 아니다. 저장 사진 인식 시험과 구분해야 한다 |
| 카메라 | CSI0/CSI1과 nvarguscamerasrc만 사용한다 | USB B0478 연결, 노출과 초점 제어, 설정 저장은 미구현이다 |
| J4012 호환 | Windows 소프트웨어 시험과 오프라인 배포 묶음이 있다 | ARM64 설치, CUDA 추론, GPIO, USB 영상과 장시간 운전을 실제 J4012에서 검증하지 않았다 |

코드 근거: station/app.py의 device_test와 camera_frame, station/hardware.py의 GpioIO와 Camera, station/schema.py의 StationConfig, ocr/frontend/src/screens/Equipment.tsx.

현재 해상도 설정은 최대 3280×2464로 제한되어 있다. B0478의 3840×2160, 4000×3000, 8000×6000은 이 검증을 통과하지 못한다. 소스 문자열만 USB 장치 경로로 바꾸어도 현재 Camera 구현에서는 거절된다.

## B0478 사양과 의미

| 항목 | 공식 공개 사양 |
|---|---|
| 센서 | Sony IMX586, 48MP, 롤링 셔터 |
| 연결 | USB 3.2 Gen 1, 카메라 쪽 Type-C, UVC |
| 영상 | YUY2 |
| 최대 해상도 | 8000×6000, 3fps |
| 비교할 모드 | 4000×3000 14fps, 3840×2160 20fps, 2000×1500 50fps, 1920×1080 60fps, 1280×720 120fps |
| USB 2.0 | 1280×720 10fps로 표기 |
| 초점 | 전동 렌즈의 수동 제어. 기본 초점 범위 3m부터 무한대, 프로그램 조절 범위 10cm부터 무한대 |
| 노출 | 자동과 수동 |
| 기타 제어 | 게인, 자동과 수동 화이트밸런스, 밝기, 대비, 채도 |
| 렌즈 | F1.8, 5.1mm, 수평 화각 65도 |
| 전원 | 5V, 최대 2W |

근거: [Arducam B0478 제품 사양](https://www.arducam.com/arducam-imx586-48mp-motorized-focus-usb-3-0-camera-module-b0478.html), [공식 데이터시트](https://www.arducam.com/downloads/datasheet/B0478_48MP_IMX586_USB3.0_Camera_Datasheet.pdf).

전동 초점은 화면의 값을 바꿔 렌즈를 움직일 수 있다는 의미다. B0478 사양의 UVC 초점 항목은 Manual이며, 자동 초점 지원을 전제로 개발하면 안 된다. 근거리 라벨 촬영에서는 기본 초점을 그대로 쓰지 말고 실제 설치 거리에서 조절해야 한다.

위 표는 제조사 수치다. 납품된 카메라의 지원 모드, 제어 범위, 실제 적용값과 프레임 속도를 읽어 다시 확인한다. 최소 노출 시간, 초점 제어 숫자 범위, 하드웨어 트리거와 센서 노출 시각 제공 여부는 공개 사양만으로 확정하지 않았다.

## J4012에서의 연결과 첫 시험

J4012의 모듈은 Jetson Orin NX 16GB다. 본체의 USB 3.2 호스트 포트에 카메라의 USB A to C 케이블을 연결한다. 본체의 USB-C Device/Debug 포트와 구분한다. 본체 사양과 BSP는 일반 J4012 또는 Mini 제품의 문서와 혼용하지 않는다. [Seeed Industrial 공식 문서](https://wiki.seeedstudio.com/reComputer_Industrial_Getting_Started/)

B0478은 UVC 장치이므로 Linux의 USB 영상 경로를 사용한다. 기존 CSI 설정과 IMX219 드라이버 절차를 적용하지 않는다. Jetson의 USB UVC 경로는 V4L2이며, 앱에서는 V4L2 또는 GStreamer v4l2src를 사용하는 카메라 어댑터가 필요하다. [NVIDIA R36.4 카메라 API 안내](https://docs.nvidia.com/jetson/archives/r36.4/DeveloperGuide/SD/CameraDevelopment/CameraSoftwareDevelopmentSolution.html)

카메라 단독 시험은 전체 공정 앱의 완성을 기다리지 않고 할 수 있다. Arducam은 Linux 시험 도구로 qv4l2와 Python OpenCV 예제를 안내한다. qv4l2에서는 재생 전에 해상도와 프레임 속도를 고르고 카메라 제어 항목에서 노출과 초점을 조절한다. [Arducam USB3 Linux 사용 방법](https://docs.arducam.com/UVC-Camera/USB3-UVC-Camera-Kit/Quick-Start-Guide-for-Linux/)

인터넷이 없는 현장에서 설치까지 가능하려면 usbutils, v4l-utils, qv4l2와 의존 패키지를 대상 Ubuntu와 ARM64에 맞춰 미리 묶어야 한다. 현재 Windows 배포 ZIP에 이 Jetson 설치물이 들어 있다고 간주하면 안 된다.

J4012에서 먼저 아래 조회를 실행한다. 이 명령은 모터와 릴레이 출력을 조작하지 않는다.

```bash
cat /proc/device-tree/model
cat /etc/nv_tegra_release
uname -m
python3 --version
dpkg-query -W nvidia-l4t-core nvidia-jetpack
lsusb
lsusb -t
v4l2-ctl --list-devices
```

nvidia-jetpack 메타 패키지가 없을 수도 있으므로 그 조회 실패 하나만으로 BSP 미설치를 판정하지 않는다. USB 연결 속도와 카메라 장치 경로를 기록한다. /dev/video0이 반드시 B0478이라는 가정은 하지 않는다.

아래 CAMERA 경로는 앞에서 확인한 실제 영상 장치로 바꾼다. 가능하면 /dev/v4l/by-id 또는 /dev/v4l/by-path 식별자를 사용하고, 재연결 시 다른 카메라를 선택하지 않는지 확인한다.

```bash
CAMERA=/dev/video0
v4l2-ctl -d "$CAMERA" --all
v4l2-ctl -d "$CAMERA" --list-formats-ext
v4l2-ctl -d "$CAMERA" --list-ctrls-menus
```

장치와 모드 조회는 [Arducam Linux V4L2 안내](https://docs.arducam.com/UVC-Camera/USB2-UVC-Camera-Kit/Quick-Start-Guide/Linux/)의 공통 명령을 따른다. 이 USB2 안내의 다른 카메라 영상 형식을 B0478 지원 사양으로 옮기지는 않는다.

조회가 끝나면 qv4l2를 열어 확인한 장치를 선택하고 다음 순서로 시험한다. 해당 도구가 카메라를 사용하는 동안 다른 프로그램에서 동시에 스트림을 열지 않는다.

1. 실물 목록에 있는 1920×1080 모드로 영상과 USB 연결 안정성을 먼저 확인한다.
2. 조명과 실제 촬영 거리를 고정하고 수동 초점으로 라벨 글자를 맞춘다.
3. 수동 노출을 선택해 흰 라벨의 글자가 날아가지 않는 값을 찾는다. 게인과 화이트밸런스도 기록한다.
4. 4000×3000과 8000×6000 등 실물 지원 모드로 같은 제품을 촬영해 기존 OCR로 비교한다.
5. 저장된 사진의 실제 크기, 실제 FPS, 제어값 재조회, 재연결 후 복원, 영상 중단과 검은 프레임 여부를 기록한다.

V4L2 표준 exposure_absolute 단위는 100µs이지만, 실제 제어 ID와 장치 반영을 확인한 뒤 UI의 ms 값과 연결한다. focus_absolute의 단위는 거리 단위로 정의되어 있지 않다. 숫자를 임의로 cm로 표시하지 않는다. 자동 노출이 활성화된 상태에서 수동 노출 쓰기를 성공으로 처리하지 않는다. [Linux 카메라 제어 규격](https://www.kernel.org/doc/html/latest/userspace-api/media/v4l/ext-ctrls-camera.html)

이 절차는 현장 실행 안내다. 이번 조사에서 J4012나 카메라를 조작하거나 영상 시험을 실행하지 않았다.

## 필요한 개발 순서

### 1. 장치를 각각 시험할 수 있게 분리

센서 입력만 읽는 시험은 아직 정해지지 않은 출력 극성이나 제품 검출 라이브러리 때문에 차단되지 않도록 별도 경로로 만든다. 생산 운전 승인 조건은 그대로 유지한다. 카메라 단독 촬영과 RFID 읽기도 각각 독립해서 점검한다.

| 시험 대상 | 제공할 시험 | 표시와 판정 범위 |
|---|---|---|
| 모터 | 시간 제한을 둔 짧은 가동, 즉시 정지, 허가 상실과 접촉기 응답 확인 | DO1 명령과 KM2 피드백을 구분한다. KM2 OFF만으로 축의 완전 정지나 실제 속도를 계측했다고 표시하지 않는다 |
| LED | 독립 켜기와 끄기, 제한 시간 종료, 카메라 영상에서 점등 영향 확인 | DO2 명령을 표시한다. 밝기 센서나 전류 피드백이 없으면 실제 점등은 사용자 확인으로 기록한다 |
| 센서 | 각 센서의 감지와 해제, 반복 감지, 변화 횟수와 시각 확인 | raw 값과 실측 극성에 따른 감지 상태를 구분한다 |
| 카메라 | 영상 확인, 한 장 촬영, 해상도와 노출 및 초점 변경, 설정 저장과 복원 | 실제 수락한 설정, 프레임 크기와 FPS, 끊김과 오류를 기록한다 |

현재 US-52 구성의 모터 속도는 현장에서 조절한다. 속도 측정이나 소프트웨어 속도 제어가 구현되어 있다고 표시하지 않는다. LED는 릴레이 ON/OFF 기준이며 조광 또는 스트로브 기능은 드라이버 사양 확인 없이 약속하지 않는다.

DI 시험에서는 입력 채널별 raw 값, 감지 상태, 변화 시각과 횟수를 보여 준다. 감지 상태 변환은 실측한 극성이 있을 때만 표시한다. DI를 읽기 위해 DO를 함께 요청하거나 방향을 변경하지 않는다.

출력 시험은 배선과 OFF 극성을 확인한 뒤에 추가한다. 모터 동력을 분리한 릴레이 점검부터 시작하고, 실제 모터 시험은 물리 정지 회로와 허가 피드백 검증 후 진행한다. 시험 시간 제한, 조작 해제 시 OFF, 접속 단절 시 OFF, 생산 작업과의 상호 배제가 필요하다. 소프트웨어 시간 제한이 OS 정지 시 차단을 보장한다고 간주하지 않는다.

현재 GpioIO의 lease 만료 조건은 motor_requested를 기준으로 검사한다. LED만 켜는 시험을 추가할 때 이 조건을 그대로 쓰면 조명 단독 시험의 시간 제한이 보장되지 않는다. 모든 시험 출력에 개별 종료 조건을 적용하고, 모터와 LED가 상대 출력을 뜻하지 않게 켜지 않는지 검증해야 한다.

### 2. B0478 연결과 설정

USB 카메라 장치 검색, 실제 지원 해상도/FPS 조회, UVC 제어 조회와 읽기/쓰기를 구현한다. Camera 추상화 아래에 CSI와 USB 경로를 분리하고, 해상도 검증을 실제 장치 능력과 자원 한도에 맞게 수정한다.

지원 목록과 min/max/step/메뉴를 장치에서 읽는다. 요청한 설정과 장치가 실제 수락한 값을 비교한다. 저장 성공은 값 재조회와 새 프레임 확인까지 성공한 경우로 제한한다. 실패하면 마지막 정상 설정으로 복원하고, 복원 실패 시 검사 시작을 차단한다.

해상도 변경은 스트림 재시작이 필요할 수 있다. 생산 작업 중에는 변경하지 않고, 변경 전 영상이나 초점 이동 중 프레임을 검사에 사용하지 않는다. 설정 버전과 실제 카메라 식별자를 검사 증거에 연결한다.

현재 Camera.after는 호스트 수신 시각과 새 프레임 수를 사용한다. USB 버퍼에 남아 있던 이동 중 프레임까지 정지 후 영상으로 인정할 위험을 검증해야 한다. 센서 노출 시각을 얻을 수 없다면 이 사실을 남기고, 실제 장치의 최대 지연과 노출 시간을 포함해 프레임 폐기와 대기 기준을 실측한다.

### 3. 기존 화면에 조절 기능 추가

환경 설정의 카메라 항목에 영상, 지원 해상도 선택, 노출 자동/수동, 노출값, 초점, 게인과 화이트밸런스, 적용과 저장을 추가한다. 노출과 초점은 큰 조절 버튼과 숫자를 함께 제공한다. 지원하지 않는 제어는 사용할 수 있게 표시하지 않는다.

장비 점검에는 촬영 시험과 결과 사진, 연결 상태, 실제 해상도와 FPS를 보여 준다. 자세한 설명은 오른쪽 i 도움말에 둔다. 생산 화면은 저장된 설정을 사용하고 작업자가 매번 카메라 값을 입력하지 않게 한다. 기존 메인과 계수 흐름을 유지한다.

초기에는 카메라 공통 설정을 사용한다. 브랜드마다 별도의 초점/노출 설정을 자동으로 도입하지 않는다. 장비 시험으로 제품 수량이나 생산 합격 기록이 늘어나서는 안 된다.

### 4. Jetson 배포와 피드백 루프

인수인계 v1.1의 JetPack 6.1 GA / L4T 36.4.0 / Ubuntu 22.04 / Python 3.10을 검증 기준으로 유지한다. 현재 장비가 이 버전인지 먼저 조회한다. 필요한 경우 Industrial J4012에 맞는 Seeed BSP와 해시를 확인해 별도로 배포를 준비한다. 카메라 시험을 이유로 바로 재플래시하거나 최신 JetPack으로 바꾸지 않는다. J4012의 MAXN SUPER 제한도 유지한다.

기존 PARSeq와 사용자 검출 기술을 유지하며 Jetson용 PyTorch/TorchVision, CUDA, OpenCV 영상 백엔드, zxing-cpp, libgpiod 2.x와 직렬 통신 패키지를 ARM64에서 실제 설치하고 시험한다. Windows wheel을 복사하는 것으로 대체할 수 없다. 의존성은 대상 장비 조합에 맞춰 로컬에 고정한다.

반복 순서는 단위 시험, 모의 장치 통합 시험, J4012 단독 장치 시험, 정지 상태 실제 제품 시험, 공정 연동과 고장 시험이다. 실패할 때 원인과 수정, 재시험 증거를 같은 항목에 남긴다. 브라우저 직접 시각 검토는 사용자 지시 후 진행한다.

## 시험 통과의 근거

| 단계 | 통과 증거 |
|---|---|
| 장치 인식 | J4012 모델, BSP, 카메라 식별자, USB 속도, 지원 모드와 제어 목록 |
| 카메라 제어 | 설정 전후 재조회, 원본 사진, 실제 크기와 FPS, 재연결 복원 |
| 센서 | 입력별 반복 감지와 해제, 극성, 변화 횟수, 단선 시 결과 |
| 출력 | 기본 OFF, 허가 상실과 시간 만료 시 OFF, 독립 정지 회로와 접촉기 실제 반응 |
| LED | 독립 점등과 소등, 제한 시간 종료, 명령과 실제 점등 확인의 구분, 모터가 함께 켜지지 않음 |
| AI | 기존 모델 해시, Jetson CUDA 실행 결과, 같은 실제 사진의 판독 비교 |
| 정지 검사 | 이동 중 프레임 배제, 정지 후 안정화, 한 제품 한 건, 불일치 또는 누락 시 정지 |
| 연속 운전 | 인수인계의 실제 제품 및 연속 운전 기준, 온도, 메모리, USB 오류, 지연 분포 |

48MP를 초기 고정값으로 채택하지 않는다. 공식 3fps에서 프레임 간격은 약 333ms이며, 현재 두 새 프레임 대기는 위상에 따라 대략 333~667ms가 들 수 있다. 이는 캡처 시간만의 계산이며 노출과 전송, OCR, 안정화, 기계 동작 시간은 별도다. 해상도별 판독 성공률과 전체 검사 시간을 측정해 촬영 모드를 결정한다.

우선순위는 독립 장비 시험 기능과 B0478 제어, 실제 J4012 설치 검증이다. 최종 생산 운전 승인과 목표 처리량은 현장 시험 전까지 미확정으로 둔다.

## 이동 중 촬영 요구의 후속 검토

이 요구는 2026년 9월 18일 최신 사용자 결정으로 기록한다. 현재 운전 코드는 변경하지 않았다. 장치별 초기 시험과 별개로, 촬영 방식 변경을 진행할 때 아래 항목을 검증한다.

1. 실제 벨트 속도, 제품 간격, 촬영 거리, 화면 내 이동 방향을 측정한다.
2. B0478의 롤링 셔터 왜곡과 노출 중 번짐을 실제 인쇄 글자로 확인한다. 높은 픽셀 수가 움직임 선명도를 보장하지 않는다.
3. 노출 시간과 조명량을 함께 조절한다. 릴레이 제어를 고속 스트로브나 카메라 동기 신호로 간주하지 않는다.
4. 센서 감지와 영상 및 RFID 읽기 결과가 같은 제품에 속하는지 검증한다. USB 수신 시각만으로 촬영 시점을 확정하지 않는다.
5. 제품 중복 계수 방지와 불일치 또는 미판독 시 정지 원칙을 유지하면서 공정 상태 전이를 다시 설계한다. 실제 정지 거리도 측정한다.

구체적 해상도, 노출값, 속도와 촬영 트리거 방식은 이 후속 시험 결과로 결정한다.
