# 원본 UI 복구와 로직 검증

기준은 reference/legacy_frontend의 사용자 원본이다. 새 디자인으로 대체하지 않는다. 추가 요구사항은 기존 화면 안에서 연결한다. 이 문서는 소프트웨어 복구 검증 기록이다. 실물 승인과 브라우저 시각 검토는 별도다.

## 검증 루프

1. 원본 기능과 사용자 요구사항을 아래 표에 기록한다.
2. 원본 화면 위치를 보존한 채 실제 API와 연결한다.
3. 백엔드 정상 동작과 고장 경로를 시험한다.
4. jsdom에서 화면 이동, 입력, 버튼, 오류 복구를 시험한다.
5. HTTP와 WebSocket으로 전체 흐름을 시험한다.
6. 실패를 수정하고 해당 시험 및 영향 범위를 다시 실행한다.
7. 실행 결과와 미확인 조건을 기록한다. 실물 없는 시험을 실물 통과로 표시하지 않는다.

## 미확정 사항

제품 검출 라이브러리 연결과 장비 실측은 기존 미확정 조건이다. 단순 계수에서도 제품 검출 및 정지 회로 검증을 우회하지 않는다.

품번, 색상, 사이즈를 읽는 고정 OCR 영역 방식은 사용자 합의 없이 추가되었다. 기존 자동 추출 코드와 별도 구현된 경로라는 사실을 유지하며, 기술 검증 및 사용자 논의 없이 확정된 요구사항으로 취급하지 않는다.

브라우저와 스크린샷 검토는 사용자 지시 전까지 하지 않는다. 사용량은 작업 10회마다 잔여 비율을 기록한다.

## 수정과 재검증 기록

1. 원본 화면을 실제 station API와 연결했다. 기존 mock API를 운영 서버로 사용하지 않았다.
2. 비밀번호만 받는 설정 진입을 복구하고 별도 역할 없는 수동 보정과 복구를 시험했다. 설정을 닫아도 작업은 유지한다.
3. 작업 생성 중복 입력 방지, 응답 유실 후 처리 결과 조회, 요청 중 STOP 우선 조작과 복구 후 자동 출발 금지를 시험했다.
4. 검사 사진과 결과 조회를 작업 기록에 연결하고 작업별 조회 및 추가 페이지를 검증했다. 최근 200건 밖의 과거 로그를 날짜로 조회할 수 있도록 수정하고 재시험했다.
5. 장비 점검 중 새 작업이 들어오는 경로를 차단했다. HTTP 요청이 끊겨도 실제 점검 스레드가 끝나기 전에는 잠금을 풀지 않는다. 서버 종료 시 점검 스레드 종료를 기다린다.
6. 사진 시험의 가상 모터 값을 실제 접촉기 상태처럼 보여 주던 부분을 수정했다. 연결이 끊기거나 미연결이면 정상 상태로 표시하지 않는다.
7. 테스트 코드의 필수 countMode 누락으로 TypeScript 검사가 실패한 것을 수정했다. 동작 테스트와 빌드를 다시 통과했다.
8. 기존 실제 사진 인식을 포함한 97개 기능 시험과 로컬 HTTP 및 WebSocket 통합 시험을 통과했다. 프론트엔드 최종 결과는 verification/restoration-frontend.json에 보관한다.

원본 통과 사진 저장, 비밀번호 변경과 날짜별 작업 로그를 연결했다. 이동 중 임계선 위치는 정지 검사 방식과 맞지 않아 비활성화한 것이며, 현재 방식과 이유를 설정 도움말에 표시한다. 원본 종료 버튼의 창 닫기 제한도 운영 문서에 명시했다.

사용량은 이번 복구 작업 10, 20, 30, 40, 50, 60회에서 잔여 76%, 74%, 73%, 73%, 72%, 71%였다. 잔여 50% 제한을 넘지 않았으며 리셋 크레딧을 사용하지 않았다.

최종 프론트엔드 시험 20개와 TypeScript 빌드가 통과했다. 8000번 서버를 갱신하기 전에 SQLite 일관성 백업을 만들었고 진행 중인 작업이 없음을 확인했다. 갱신 후 비밀번호 저장값이 백업과 동일하며 DB 무결성, 원본 화면 경로, 정적 파일, 계정 없는 작업 진입과 설정 잠금을 실제 HTTP로 확인했다.
