# RFID 시험

시험 화면의 RFID 탭에서 태그 읽기를 누른다. 저장된 포트가 없거나 열리지 않으면 USB 직렬 포트가 하나뿐일 때 그 포트를 리더로 사용하고 저장한다. USB 직렬 포트가 없으면 직렬 포트가 하나뿐일 때 그 포트를 사용한다. 후보가 여러 개이면 탭에 포트 선택이 나타나며 고르는 즉시 저장한다. 별도의 명령 규격 확인 단계는 없다. 읽기 중에는 포트를 변경할 수 없다. 리더의 영문 오류 상세는 기록에 남기고 화면에는 RFID 응답이 없습니다 또는 RFID 리더 오류로 표시한다.

RFID 탭의 리더 설정에서 송신 출력값을 변경한다. 기본값은 2600이며 2000은 20dBm, 2600은 26dBm이다. 소프트웨어 입력 범위는 0~2600이고 실제 장비가 받는 범위는 초기화 응답으로 확인한다. 저장한 출력은 RFID 시험과 생산 운전에 함께 사용하며 재시작 후에도 유지한다. 이미 연결된 생산 리더는 저장 시 출력 SET과 GET 일치를 확인한다. 장비가 값을 거부하거나 조회값이 다르면 저장 성공으로 처리하지 않는다. 읽기 중과 생산 작업 중에는 변경할 수 없다.

태그 읽기의 결과와 오류는 RFID 탭에 표시된다. 모터와 LED를 켠 상태에서도 읽을 수 있고, 읽는 동안 출력 스위치도 조작할 수 있다. 동일 포트의 중복 읽기와 생산 작업 중 읽기는 차단한다. 리더 초기화 검증은 유지한다.

초기화는 한국 지역 0x06을 조회하고, 다른 지역일 때만 변경한 뒤 조회로 확인한다. 이어서 자동 주파수 호핑을 켜는 0xAD/0xFF 명령과 성공 응답을 확인하고 저장된 출력을 적용한다. 초기화 명령의 응답 대기는 각각 최대 1초다. 호핑이나 출력 설정이 실패하면 준비 완료로 처리하지 않는다.

시험은 0x27로 5회 읽기를 요청한다. 읽기 시간은 전체 대기의 상한이며 기본값은 5000ms다. 태그 또는 15 응답을 받은 뒤에는 마지막 응답부터 500ms 동안 추가 응답을 기다리고, 전체 상한 안에서 종료한다. 시작부터 500ms가 지났다는 이유로 첫 태그를 놓치지 않는다. 종료나 취소 시에는 0x28을 전송한다. 기존 500ms 설정은 업데이트 후 처음 실행할 때 5000ms로 변경한다. 다른 시간 설정과 출력값은 유지한다. 업데이트 후 사용자가 다시 500ms로 저장하면 다음 실행에서도 그 값을 유지한다.

읽기 중 15 응답은 해당 회차에서 유효한 태그를 읽지 못했다는 뜻이다. 이미 읽은 태그는 유지하며, 추가 응답에서 읽은 태그도 모은다. 끝까지 태그가 없으면 읽은 태그 0개로 표시하며 다시 읽을 수 있다. 읽기 응답이 전혀 없으면 RFID 응답이 없습니다로 표시한다. 공유 리더가 무응답이나 오류로 초기화되지 않은 상태가 됐을 때는 다음 태그 읽기에서 지역, 호핑, 출력을 다시 초기화한다. 이는 EN 핀을 이용한 하드웨어 재시작이 아니다. 다른 장비 오류나 직렬 통신 프레임 손상은 오류로 처리한다.

USB 장치 인식과 직렬 포트 생성은 별개다. 목록은 운영체제가 제공한 직렬 포트이며 USB 장치 목록 전체가 아니다. USB가 보이더라도 직렬 포트가 생성되지 않으면 해당 리더의 연결 방식과 드라이버를 확인해야 한다. 실제 장비 수신은 별도 현장 확인이 필요하다.

모터와 LED 켜기 버튼은 설정 차단 사유만으로 비활성화하지 않는다. 요청 시 서버가 검증하며, 거부 사유를 화면 상단 오류 줄에 표시한다. 이미 켜진 출력과 1초 연속 조작 제한, 요청 처리 중 중복 클릭은 계속 방지한다.

## 2026-10-21 근거 확인

수정 전에 저장소의 인수인계 v1.1 정리본 [HARDWARE_ACCEPTANCE.md](HARDWARE_ACCEPTANCE.md)를 확인했다. USB-TTL YRM1006, 115200 8N1, EN 고정 구성과 읽기 0x27, 태그 응답 0x22가 기록돼 있다. 정리본에는 호핑 설정이나 이번 시험의 5회 읽기 및 5초 대기 조건이 없다. 원본 인수인계 파일은 현재 작업 공간과 저장소 이력에서 찾지 못해 원문 기재 여부는 확인하지 못했다.

사용자가 제공한 `yrm100_pico_nonblocking.py`의 설정과 초기화 명령을 대조했다. 이 코드의 호핑 0xAD/0xFF, 시험 읽기 5회, 최대 5초와 마지막 응답 이후 500ms 대기를 반영했다. Pico는 15에서 즉시 결과를 종료하지만 현재 프로그램은 추가 태그를 놓치지 않도록 위 대기 범위 안에서 계속 수집한다. Pico의 EN 재시작은 현재 고정 배선에서 지원하지 않는다. Pico의 출력 2000으로 강제 변경하거나 출력 설정 실패를 무시하지 않으며 저장된 출력과 SET/GET 일치를 유지한다. 생산의 제품별 최대 횟수, 간격, 첫 성공에서 종료하는 동작은 [RFID_RETRIES.md](RFID_RETRIES.md)를 따른다.
