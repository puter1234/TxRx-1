# 실무 개선 구현 기록

기준일: 2026-10-16 (Asia/Seoul)

[요구사항](WORKFLOW_REQUIREMENTS.md), [수정 전 검토](WORKFLOW_UX_REVIEW.md)를 기준으로 구현했다. 아래의 소프트웨어 검증과 실제 장비 검증은 구분한다.

## 운전 흐름

생산 작업과 프리셋의 `이 설정으로 시험`은 같은 `station/flow.py`를 사용한다. 시험 작업은 기록에 남으며 생산 통계에서는 기본적으로 제외한다. 기존 센서 프레임 수집 화면은 개별 장비 진단용이다. 생산 순서를 확인할 때는 프리셋 시험을 사용한다.

1. DI1의 최초 0 신호에서 LED를 켜고 DO4를 OFF로 요청한다. 저속 상태다.
2. 신호가 설정한 시간 동안 유지되면 제품 ID를 만들고 검사를 시작한다. 타이머 기준은 최초 신호 시각이다.
3. 저속 유지 종료, 카메라 촬영, RFID 확인은 독립적으로 실행한다. OCR 처리 시간 때문에 다음 촬영 간격이 밀리지 않도록 사진을 먼저 정해진 간격으로 수집한다.
4. DI2 최초 0 신호에서 LED를 끈다. 신호 유지 시간을 충족하면 통과 기록을 한 번 남긴다.
5. 같은 제품의 검사 결과와 DI2 통과가 모두 확인되어야 수량을 올린다. 비전 계수는 추적 객체의 통과가 정확히 1개여야 한다. 검사 불일치나 복수 검출은 즉시 정지하고, 미판독과 미도착은 각각 제한시간을 적용한다.

센서는 안정된 1 상태를 확인한 뒤 다시 감지할 수 있다. 초기 가림, 계속 가림, 짧은 신호 흔들림을 반복 계수하지 않는다. DI1과 DI2 신호 유지 시간은 프리셋에 각각 저장한다. 기본값은 실측값이 아니며 10ms 소프트웨어 감시 주기를 사용한다. 1ms 정확도를 보장하지 않는다.

목표 수량에 도달하면 작업을 완료하고 정지한다. 수동 정지, 오류 해제, 제품 제거, 수량 보정은 별도 기록을 남긴다. 사진 인코딩과 저장은 감시 루프 밖에서 실행하며, 저장 중 정지된 제품의 늦은 결과를 합격 수량에 추가하지 않는다. 여러 장 촬영의 보관 대상 사진을 모두 저장하고, 불일치가 발생한 사진을 대표 증거로 사용한다. 합격 사진 미보관 설정도 유지한다. 프레임 메모리는 가용 메모리의 25%와 1GB 중 작은 값으로 제한한다.

## 카메라와 재연결

카메라 설정, 미리보기, 단일 촬영, 연속 촬영, OCR 시험을 하나의 장비 테스트 화면에서 사용한다. 탭 이동 후 설정 초안과 결과를 유지하고, 모터와 LED 시험도 유지한다. 처음 화면으로 나가면 시험 I/O를 정상 종료한다. 저장 전 시험 적용, 저장된 값, 실제 장치 값을 구분한다. 생산 시작 전 READY 상태에서는 작업을 버리지 않고 카메라를 조정할 수 있다.

지원되는 자동 초점과 자동 화이트밸런스를 끄고 수동값을 명시적으로 적용한다. 저장된 과거 프로필로 재연결할 때도 같은 경로를 사용한다. 스트림을 연 뒤 장치값을 다시 읽어 검증한다. 사진 시험, 센서 프레임 시험, 생산 촬영 전에 실제 고정값이 바뀌었는지도 확인한다. 프레임에는 설정 버전과 프로필을 함께 기록한다. 미리보기는 축소 JPEG이고 저장 사진은 원본 PNG다. 화면에서 촬영 결과와 다운로드 파일은 같은 PNG를 사용한다.

카메라 의존 작업에서 영상이 끊기면 모터를 멈추고 설정한 간격으로 재연결한다. 센서만 쓰는 단순 계수는 카메라나 사용하지 않는 RFID 상태로 중단하지 않는다. 복구 시 같은 제품 ID와 완료된 결과를 유지하고, 중단 시간만큼 타이머를 연장한다. 미완료 검사만 다시 실행한다. 연결 중 사용자가 정지했거나 다른 오류가 발생했다면 자동으로 재가동하지 않는다. 미촬영 제품이 단절 중 DI2를 통과했다면 합격 처리하지 않고 원인을 기록한다.

## DO4

`StationConfig.speed_line`에 실제 GPIO offset을 지정한다. `do_lines`의 DO1과 DO2는 기존 배치를 유지한다. 생산 어댑터, 시험 어댑터, 생산 I/O 대여 어댑터 모두 속도를 별도 출력으로 처리한다. ON은 NC 접점 개방에 따른 고속, OFF는 저속이다. 장비 테스트에는 고속과 저속 버튼이 있다.

저장소에서 DO4의 GPIO offset을 확인할 근거를 찾지 못했으므로 기본값은 `null`이다. DO4라는 이름을 GPIO 4로 바꾸지 않았다. 관리자 작업 설정의 DO4 연결 설정에서 저장할 수 있고, 서버 재시작 후 적용한다. 중복 핀 배정은 거부한다. 미설정 상태에서는 실물 운전을 시작할 수 없다.

## 와펜 계수와 모델

- CVZone: 밝기 임계값, 반전, 최소 면적, ROI로 윤곽을 검출한다.
- YOLO26: 로컬 `.pt`와 `.onnx` 검출 모델을 지원한다. 신뢰도, 클래스, 입력 크기, ROI를 설정한다. 없는 모델을 자동 다운로드하거나 다른 방법으로 전환하지 않는다.
- 공통 추적: 중심 좌표로 객체를 연결하고 설정된 방향으로 계수선을 통과한 ID를 한 번만 센다. 계수선 여유, 최대 이동 거리, 추적 유지 시간을 설정한다. 처음부터 선을 지난 위치에서 나타난 객체는 통과한 것으로 추정하지 않는다.
- 작업이 바뀌면 추적 상태를 초기화한다. 같은 경로의 모델 파일이 교체된 경우도 해시로 구분해 다시 불러온다. 적용한 모델 경로와 SHA256을 작업 기록에 남긴다.
- 작업 화면에 모델 이름과 검출 위치, 계수선을 표시한다. 검출 그림은 최근 처리 프레임 결과이며 현재 미리보기와 수신 시각이 다를 수 있다.

실행 의존성은 `requirements-counting.txt`에 있다. 기존 PyTorch와 TorchVision 설치를 유지하고 기본 요구사항과 함께 의존성을 확인한다. ONNX Runtime은 Python 3.10의 ARM64 패키지를 제공하는 1.22.1을 사용한다. PT는 PyTorch CUDA를 사용할 수 있으면 GPU를 사용한다. ONNX는 CUDA 제공자가 있을 때 GPU를 사용하고 나머지는 CPU를 사용한다. 클라우드 CPU 실행과 ARM64 wheel 확보를 검증했으며 Jetson에서의 추론 속도는 실측하지 않았다.

## 작업 화면과 프리셋

처음 화면에서 등록된 작업과 브랜드 옵션, 목표 수량을 선택한다. 작업자는 알고리즘, 모델 경로, 검사 채널을 수정하지 않는다. 관리자 작업 설정에서 기능, 브랜드, 계수 방법, 모델, 촬영, 타이밍, 센서값을 편집하고 복사하거나 사용을 중지할 수 있다.

프리셋은 버전으로 충돌을 확인하고, 시작한 작업에 설정 사본을 고정한다. 이후 프리셋을 수정해도 진행 중인 작업이 바뀌지 않는다. 설정 화면과 장비 테스트를 오갈 때 같은 관리자 인증을 사용하며, 작업 설정 초안을 유지한다. 이전 작업 불러오기는 등록된 작업 선택 화면으로 연결한다. 이전 옵션이 현재 브랜드에 없으면 선택을 다시 확인해야 한다.

새 문구에는 엠 대시와 가운뎃점을 사용하지 않았다. 수량 단위는 개다. 수량, 운전 상태, 모델, 센서 상태와 실행 버튼을 우선 표시하고 상세 진단은 펼쳐서 확인한다.

## 통계

작업 기록에서 기간, 브랜드, 프리셋으로 조회하고 시험 작업 포함 여부를 선택한다. 작업별, 일자별, 검사별 CSV를 제공한다. CSV는 UTF-8 BOM과 한국어 열 이름을 사용한다.

수량, 합격, 불합격, 보정, DI1과 DI2, 비전 통과, 재연결 시도, 오류, 재검사, 미판독, 불일치, 운전과 정지시간, 평균 및 최대 검사시간, 분당 수량, 모델 파일과 해시를 저장된 자료로 집계한다. 검사 상세에는 제품 ID, 검사 차수, 실제 실행 지연, 모델 처리 시간, 불합격 사유를 포함한다. 카메라와 RFID의 실행 지연은 호스트 기준이며 센서 노출 시각이나 리더 내부 시각의 측정값이 아니다.

날짜는 Asia/Seoul 기준이다. 자정을 넘는 운전과 정지시간은 날짜별로 나누고, 수량은 판정 완료 시각에 반영한다. 작업별 조회는 기간과 겹치는 작업의 전체 합계이고, 일자별 조회는 기간 안에 발생한 수량과 시간이다. 기존 기록에 없었던 DI2, 모델, 종료 시각 등은 과거 데이터에서 복원했다고 표시하지 않는다.

## 검증

- 장비 및 서버 회귀: `tests_station` 155개 통과, 비공개 표본 관련 2개 건너뜀.
- 화면 회귀: 34개 통과. TypeScript 검사와 배포 빌드 통과.
- 가짜 I/O와 시간으로 DI1과 DI2 순서, 독립 타이머, 저속 복귀, 센서 중복 억제, 카메라 단절 예외, 재연결 간격과 자동 복구, 복구 중 수동 정지, 단절 중 놓친 촬영, 불일치 즉시 정지, 늦은 저장 결과를 확인했다.
- 실제 CVZone 패키지로 합성 물체를 이동시켜 통과 수량 1개를 확인했다. 로컬에서 만든 미학습 YOLO26n을 `.pt`와 `.onnx`로 각각 불러와 CPU 추론을 실행했다. 실제 와펜 정확도를 측정한 결과는 아니다.
- Chromium 1366x768에서 실제 프론트엔드, API, 인증, WebSocket, SQLite로 프리셋 저장, 시험 작업 생성, 작업자 화면의 알고리즘 선택 미노출, 모델 표시, 통계, CSV 다운로드를 확인했다. 자바스크립트 오류와 금지 문구 기호는 없었다.
- 기존 카메라 작업 화면은 합성 하드웨어 응답으로 설정 초안 유지, 출력 유지, 이동 중 촬영, 원본 이미지 표시, READY 조정을 확인했다.
- `tests_station tests` 전체 실행에서는 169개 통과, 11개 건너뜀, 실패 2개와 오류 28개가 있었다. 비공개 `images/`가 필요한 표본 시험과 기존 `whole-image` 단계명에 대해 `original`을 기대하는 시험이다. 해당 자산이나 OCR 모델을 이번 코드 작업의 전제조건으로 요청하지 않았다.

클라우드 상세 결과는 저장소 밖 `/workspace/.txrx-implementation/`에 있다. `station-final.log`, `frontend-final.log`, `build-final.log`, `workflows-browser.json`, `model-smoke.log`와 화면 확인용 PNG를 보관한다. 이 결과는 배선, 광학 성능, 실제 RFID 태그, 컨베이어 정지거리의 실물 검증을 대체하지 않는다.

## 현장 확인과 명시적 보류

DO4 GPIO offset, DI1과 DI2 신호 폭 및 중복 억제 시간, 실제 촬영 위치와 지연, 재연결 후 제품 위치, 카메라 고정값, RFID 판독, 와펜 모델 정확도와 처리량은 실물에서 확인해야 한다. 기본값을 생산 실측값으로 취급하지 않는다.

사용자가 보류한 다음 DI1 선행 감지 처리와 와펜 이외의 탐지 대상은 미확정으로 유지한다. 선행 DI1이 들어오면 현재 구현은 정상 공정을 계속하거나 이전 제품을 덮어쓰지 않고 `EARLY_DI1_UNRESOLVED`로 중단한다. 이것은 미정 상황의 실행 차단이며, 대기열이나 연속 투입 공정을 확정한 것이 아니다.
