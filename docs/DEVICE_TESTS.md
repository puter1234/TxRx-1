# 장비 개별 시험

Git 배포 후속 변경: 짧은 모터 시험의 접촉기 응답 누락과 소유한 시험이 없는 화면의 자동 정지 요청을 수정했다. 관련 백엔드 시험은 12개 통과했다. Git 설치와 업데이트는 [J4012_GIT.md](J4012_GIT.md)를 따른다. 아래 11개 시험 결과는 최초 구현 당시 기록이다.

2026년 9월 18일 구현. J4012 실물 검증은 아직 하지 않았다.

## 사용 순서

1. 환경 설정 비밀번호로 들어가면 시험 화면이 열린다. 화면이 열려 있는 동안 센서 입력은 자동으로 연결되고 화면을 벗어나면 반환된다. 입력이 연결된 동안에는 생산 작업을 새로 시작할 수 없다.
2. 저장된 카메라 설정이 있으면 서버 시작 시 카메라를 자동으로 켠다. 연결이 끊기면 2초부터 최대 10초 간격으로 다시 연결하고 저장된 설정을 다시 적용한다. 그동안 화면 상단에 카메라 연결 중으로 표시하며 누를 버튼은 없다. 화질 탭의 카메라 끄기를 누른 경우에만 다시 연결하지 않는다.
3. 처음 설치할 때는 화질 탭에서 카메라를 고르면 바로 켜진다. 해상도, 노출, 초점 등은 바꾸는 즉시 카메라에 적용하고 저장한다. 처음 값으로는 탭을 열었을 때의 값으로 되돌린다. 촬영 전에 초점이나 화이트밸런스가 저장값과 달라져 있으면 저장값으로 되돌린 뒤 촬영한다.
4. 화면 상단에서 센서 1, 센서 2, 접촉기 상태를 확인하고 모터, LED, 속도를 바로 켜고 끈다. 모터를 끈 뒤 5초, LED 신호 변경 후 1초 동안은 켜기 버튼에 남은 초를 표시한다. 모터를 켰는데 DI3 응답이 없으면 접촉기 항목에 표시한다. 비상정지는 항상 누를 수 있다.
5. 사진 찍기는 원본 해상도로 저장하고 문자 읽기는 현재 영상의 글자를 읽는다. 결과는 큰 창으로 열리며 원본 크기 보기, 원본 저장과 판독 상세를 볼 수 있다. 여러 장은 연속 촬영이다. 시험 사진은 생산 수량에 반영하지 않는다.
6. 공정 시험 탭에서 시험 시작을 누르면 서버가 입력을 열고 저장된 카메라를 켠 뒤 수동 LED와 속도 시험을 넘겨받아 시작한다. 시험 설정은 바꾸는 즉시 저장한다. 시작할 수 없을 때는 시작 버튼에 이유를 표시한다.
7. 와펜 계수 탭은 계수 설정의 와펜 설정으로 실시간 영상에서 수량을 센다. 작업을 만들지 않는다.
8. RFID 탭에서 태그 읽기를 누르면 EPC와 읽은 횟수 및 RSSI가 나온다. 저장된 포트가 열리지 않으면 USB 직렬 포트에서 리더를 찾아 저장한다. USB 직렬 장치가 여러 개일 때만 포트를 고른다.
9. 장비 정보에서 입출력 배선과 장비 상태를 확인한다. 문서의 기본 배선(/dev/gpiochip0, DO 51과 52, DI 105와 144와 106, 운전 허가 GPIO 없음)은 고를 항목이 없다. 다른 배선은 출력 켜짐 신호, 센서 감지 신호, 운전 허가 GPIO와 확인 항목을 고르며 고르는 즉시 저장한다.

시험 화면을 벗어나거나 숨기면 정지를 요청하며, 화면 유지 신호가 1.5초 동안 없으면 서버에서 출력을 끈다. 별도의 현장 정지 회로는 계속 필요하다.

## OCR 촬영 시험

시험 화면의 문자 읽기는 현재 프레임에서 기존 `pipeline.process_task`를 호출한다. 바코드가 있으면 그 주변의 글자 줄을 기존 세그멘테이션으로 찾고, 바코드가 없으면 영상 전체의 글자 줄을 같은 세그멘테이션으로 탐색한다. 사용자가 영역을 지정하지 않는다. 검출된 글자 줄, 문자값, 신뢰도, 처리 시간을 표시한다. 시험 사진은 저장하지 않는다. 밝기 증폭, 밝기 이동, 감마, 대비, 국소 대비 보정은 실제 PARSeq 입력에 적용된다. 보정값을 저장하면 생산 검사에도 적용된다. 완전히 검게 찍힌 글자는 소프트웨어 보정으로 복구할 수 없다.

생산 검사는 같은 자동 OCR 경로를 사용한다. 읽은 전체 제품 코드를 메이커 설정에 등록된 옵션값 순서대로 유일하게 분해할 수 있을 때만 각 옵션의 관측값으로 채운다. 값이 없거나 여러 방식으로 해석되면 보류한다. 기존 수동 OCR 영역 설정은 더 이상 검사에 쓰지 않는다. 바코드 없는 영상의 전체 탐색 속도와 인식률은 현장 사진으로 별도 확인이 필요하다.

## 실행 환경

USB 카메라의 실제 제어는 Linux의 v4l2-ctl과 OpenCV V4L2 백엔드를 사용한다. J4012에 v4l-utils, libgpiod 2.x, pyserial 및 기존 앱 의존성을 로컬 설치해야 한다. 운영 중 외부 서버나 인터넷을 호출하지 않는다. Windows에서는 설정 화면과 앱을 사용할 수 있지만 J4012 GPIO와 Linux UVC 제어를 실제 연결한 것으로 표시하지 않는다.

카메라 설정은 운영 DB의 usb_camera_profile에, 시험용 입출력 설정은 bench_setup에, OCR 보정값은 ocr_correction에 저장한다. 생산 운전 승인 체크값은 자동 변경하지 않는다. USB 카메라 설정은 HARDWARE 모드로 실행할 때도 동일한 카메라 관리자가 읽는다. 사용자가 사진 촬영을 누른 시험 사진만 runtime/device-tests에 저장한다.

모터 속도는 기존 US-52에서 조절한다. LED는 릴레이 ON/OFF이며 조광과 고속 스트로브를 구현했다고 간주하지 않는다. 입력값과 접촉기 피드백은 실제 회전 속도나 실제 점등 계측과 구분한다.

## 이번 소프트웨어 시험 결과

기존 백엔드 회귀 시험 65개 통과. 신규 tests_station/test_bench.py 11개 통과. 마지막 프론트엔드 TypeScript 검사와 Vite 빌드 통과.

신규 시험은 입력 연결과 출력 분리, 시간 만료 및 화면 단절 시 OFF, 지연된 ON 요청 차단, 중복 요청, 허가 상실, 접촉기 응답 이상, 설정 비밀번호와 핀 중복 검사, 카메라 설정 저장 및 복원, 사진 저장과 생산 기록 분리, 점검 중 생산 시작 차단, V4L2 목록 파싱을 포함한다.

가짜 장치 응답을 사용한 시험이며 실물 호환 인증이 아니다. 검증 중단 지시에 따라 마지막 수정 후 전체 재시험과 신규 프론트엔드 동작 시험은 실행하지 않았다. 브라우저를 열거나 화면을 시각 검토하지 않았다.

이동 중 촬영으로의 공정 변경은 요청대로 보류했다.
