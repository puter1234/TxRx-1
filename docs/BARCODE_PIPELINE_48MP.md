# 48MP 촬영과 바코드 모델 연결

촬영 원본은 8000 x 6000이다. 원본 프레임을 유지한 채 같은 프레임을 4000 x 3000으로 축소해 위치를 찾는다. 별도로 12MP를 촬영하거나, 축소본을 다시 확대해 OCR 입력을 만드는 경로는 없다.

1. 카메라가 전달한 48MP BGR 프레임과 프레임 번호, 수신 시각을 확보한다.
2. 같은 프레임의 12MP 축소본에 YOLO26n 택 검출을 적용한다.
3. 8% 여유를 포함한 택 ROI를 12MP에서 추출하고 YOLO26n-seg로 바코드를 분할한다.
4. 바코드 주변 문자 후보의 역회전 좌표에 ROI 원점을 더하고 48MP 비율로 환산한다.
5. 해당 좌표로 보관한 48MP 원본에서 글자를 affine 보간해 추출한다. 후보 크기는 48MP 좌표의 실제 길이로 정한다.
6. 0도와 180도 방향을 모두 기존 PARSeq에 전달한다. PARSeq 내부의 고정 입력 크기 변환은 기존 공식 전처리를 따른다.
7. 시험에서는 판독 결과와 원본 크롭을 표시한다. 생산 검사에서는 등록된 브랜드 옵션과 선택한 조건으로 판정한다. 방향별 결과가 서로 다른 등록 상품을 가리키면 모호한 결과로 처리한다.

센서 시험의 미검출은 결과에 남기고 다음 제품을 계속 받는다. DO4 복귀는 저속 유지 시간, LED 소등과 계수는 DI2에 따른다. 모터 전원을 끈 뒤 재시작 제한은 5초다.

## 모델과 설치

원본 저장소는 `puter1234/barcode-pipeline`, 사용한 커밋은 `100a3025192e7ea06a1eefcf32c2b7d7b16ba9a9`다. 추론 코드, 배포 설정과 ONNX 모델 두 개를 `vendor/barcode_pipeline`에 포함했다. 시작 전 파일 해시를 확인하고 모델은 프로세스에서 한 번 불러와 재사용한다. 추론 중 다운로드하지 않는다.

택 검출은 960 입력, confidence 0.15, 바코드 분할은 640 입력, confidence 0.10이다. 원본 배포 코드의 CPU ONNX 실행과 녹색 채널 gain 3.5를 유지한다. PARSeq는 기존 장치 선택을 사용하며 Jetson에서는 CUDA를 확인한다.

기존 J4012 설치를 업데이트할 때 저장소 루트에서 현재 사용 중인 환경에 추가 패키지를 설치한다.

```bash
.venv-bench/bin/python -m pip install -r requirements-barcode-pipeline.txt
```

다른 가상환경을 사용 중이면 그 환경의 Python으로 실행한다. 새 장비는 `scripts/install_ocr_jetson.py`가 이 의존성과 모델 준비 확인을 포함한다. 업데이트와 설치 후 서버를 재시작한다.

카메라 설정에서 장비가 제공하는 8000 x 6000 모드를 적용한다. 지원하지 않거나 실제 입력이 다른 크기이면 새 모델 시험을 시작하지 않는다. 카메라 설정을 임의로 12MP로 내리거나 지원하지 않는 모드를 생성하지 않는다.

`센서 시험`과 `현재 영상 OCR 검사`의 기본 방식은 `택 검출과 바코드 분할`이다. 기존 촬영 지연, 저속 유지 시간, 장수와 간격은 유지한다. 사진과 문자 크롭은 PNG로 전달한다. 생산 작업의 OCR과 바코드 검사도 같은 모델을 사용한다. 와펜 계수용 모델 선택은 별개다.

## 확인한 범위

- 실제 ONNX 모델 두 개로 upstream 예시의 택 2개, 바코드 2개, 문자 후보 2개 검출을 확인했다.
- 연결 확인용으로 12MP 예시를 48MP 크기로 확대한 입력을 사용했다. 이는 실제 48MP 카메라 영상이나 인식률 검증이 아니다.
- 별도 합성 48MP 프레임에서 축소하면 사라지는 픽셀 무늬가 OCR 입력에 남는지 확인했다. 48MP 원본 크롭, 180도 회전, ROI 원점과 배율, PNG 표시를 검증했다.
- 카메라와 GPIO는 모의 장치로 검증한다. 실제 촬영 품질, Jetson 처리 시간과 PARSeq 인식률은 현장에서 확인해야 한다.

문자 후보 추출은 원본 저장소의 실험 구현이다. 반사, 가림, 다중 바코드에서 품번 줄이 빠지거나 다른 문구가 잡힐 수 있다. 품번의 정답을 조건값에서 만들어 넣지 않는다. 실제 모델이 반환한 문자열과 등록 규칙으로 판단한다.
