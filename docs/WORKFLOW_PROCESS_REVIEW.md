## 추가 검토와 수정

`0fbe4c6` 이후 실제 FastAPI 앱, 주기 감시, GPIO 어댑터, SQLite를 함께 실행하는 시험을 추가했다. GPIO 입력과 카메라, RFID, OCR 응답은 시험 장치로 대체했다. 정상 경로에 임의의 준비 대기 시간을 넣지 않고, API가 운전 가능하다고 응답하는 시점부터 제품을 투입했다.

카메라 자동 재연결은 같은 제품 ID로 이어지고 한 번만 계수하는지 실제 API 경로에서 확인했다. 연결 함수를 대기시킨 상태에서도 정지 요청이 반환되며, 늦은 연결 성공이 수동 정지를 되돌리지 않는지도 확인했다. 취소된 추론 함수가 아직 반환되지 않은 상태에서 다음 제품이 들어오면 정지하고, 늦은 결과가 수량을 추가하지 않는 기존 차단도 검증했다. 단순 계수는 카메라와 사용하지 않는 RFID 연결 없이 목표 수량까지 완료했다.

## 확인한 작업 흐름

1. 관리자 프리셋을 저장하고 작업자가 등록된 작업, 브랜드 옵션, 목표 수량을 선택한다. 프리셋 버전과 적용 설정은 시작한 작업에 고정된다.
2. DI1 감지 뒤 LED, 저속 유지, 촬영, RFID가 같은 제품과 기준 시각을 사용한다. DI2와 검사 결과가 모두 확인된 제품만 계수한다.
3. 검사 불일치, 예상하지 않은 DI2, 선행 DI1, 제한시간 초과는 정지한다. 느린 사진 저장 결과가 수동 정지 이후 수량을 올리지 않는다.
4. 카메라가 필요한 작업은 단절 시 정지하고 재연결한다. 수동 정지와 제품 오류가 없을 때만 자동 재가동한다. 센서 단순 계수는 카메라나 사용하지 않는 RFID 단절에 의존하지 않는다.
5. 오류 해제와 제품 제거 순서가 바뀌어도 남은 조치를 완료할 수 있다. 복구 버튼 자체가 모터를 가동하지 않는다.
6. 목표 수량 도달, 작업 종료, 서버 재시작과 늦은 검사 결과의 처리 경로를 회귀 시험으로 확인했다. 시험 작업은 생산 통계에서 기본 제외한다.
7. 한국 시간 자정 경계, 작업별 수량과 일자별 수량, CSV, 과거 기록의 누락 시각을 확인했다.

## 현장 확인과 보류

DO4의 실제 GPIO offset은 아직 지정되지 않았다. 해당 값과 기존 장비 운전 조건을 확인하기 전에는 실물 운전을 시작할 수 없다. 촬영 지연, 다중 촬영 간격, 센서 신호 유지 시간, 재연결 후 제품 위치와 실제 모델의 처리량은 장비에서 확인해야 한다.

사용자가 보류한 다음 DI1 선행 감지의 공정 정책과 와펜 이외 탐지 대상은 계속 보류한다. 현재 선행 DI1은 오류로 중단하며 연속 투입 대기열을 구현한 것으로 취급하지 않는다.
